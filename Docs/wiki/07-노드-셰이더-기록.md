# 📓 7. 노드 셰이더 기록 — 언리얼 머티리얼 에디터 (유니티 Shader Graph 대응)

> 유니티의 **Shader Graph** 처럼 노드를 연결해 셰이더를 만드는 방식을, 언리얼 5.8 의 **Material Editor** 로 젤리 룩에 적용해 본 기록입니다.
> 어떤 그래프를 왜 만들었는지, 어떤 기법을 노드로 어떻게 풀었는지, 유니티라면 무슨 노드에 해당하는지, 그리고 시행착오를 정리합니다.
> 사용법은 [바로 써보기](02-바로-써보기), 수식·HLSL 전체는 저장소의 [JellyMaterialGuide.ko.md](https://github.com/JiwonEnv/UE5-Stylized-Jelly-Lab/blob/main/Docs/JellyMaterial/JellyMaterialGuide.ko.md) 에 있습니다.

## 1. 유니티 Shader Graph ↔ 언리얼 Material Editor 대응표

| 유니티 (URP/HDRP Shader Graph) | 언리얼 (Material Editor) | 이 프로젝트에서 |
|---|---|---|
| Shader Graph 에셋 | Material (마스터 머티리얼) | `M_Jelly_Gummy` |
| Material (그래프의 Property 값만 바꾼 것) | **Material Instance** | `MI_Jelly_*` 8종 프리셋 |
| Blackboard Property | Scalar / Vector / Texture **Parameter** (+ Group) | 65개 파라미터를 9개 그룹으로 정리 |
| **Sub Graph** | **Material Function** | `MF_Jelly_RedPainted_Stars` / `InnerStars` / `InnerGlitter` |
| **Custom Function** 노드 | **Custom** 노드 (HLSL 직접 작성) | Kuwahara 유화 필터 |
| Fullscreen Shader Graph / Renderer Feature | **Post Process Material** + Post Process Volume | `M_PP_JellyPaintFilter` |
| Graph Settings → Surface Type / Material | Details → Blend Mode / Shading Model | Translucent + **Thin Translucent** |
| Fresnel Effect 노드 | Fresnel 노드 | 림, 테두리 선, 가짜 두께 |
| Triplanar 노드 | (노드 없음) → WorldPosition·VertexNormal 로 직접 조립 | 붓 자국·별 스프라이트 |
| Posterize 노드 | (노드 없음) → `Floor(x·N + 0.5) / N` | 계단 음영 |
| Simple Noise / Gradient Noise | Noise 노드 | 하이라이트 가장자리 흔들기 |
| Reflection / View Direction | ReflectionVectorWS / CameraVector | 가짜 소프트박스 하이라이트 |
| Object 노드 (Position) | ObjectPositionWS | 오브젝트 기준 높이 그라데이션 |
| Scene Color / Scene Depth | SceneTexture (PostProcessInput0, CustomStencil) | 유화 필터 입력·마스크 |
| Stencil (Renderer Feature 설정) | Custom Depth-Stencil (프로젝트 설정 + 액터 설정) | 필터를 젤리에만 적용 |

> 한 줄 요약: **개념은 거의 1:1** 입니다. 차이는 언리얼이 Triplanar·Posterize 같은 편의 노드가 적어 직접 조립해야 하고, 대신 Material Instance 와 파라미터 그룹 관리가 강력하다는 점.

## 2. 만든 그래프 목록

| 그래프 | 종류 | 노드 수 | 파라미터 | 픽셀 셰이더 명령어 | 목적 |
|---|---|---:|---:|---:|---|
| `M_Jelly_Gummy` | 마스터 머티리얼 | 441 | 65 | 2,455 | 룩데브용 "만능" 젤리. 모든 효과를 파라미터로 켜고 끔 |
| `MI_Jelly_*` (8종) | 머티리얼 인스턴스 | – | – | – | 사실적(Raspberry/Blue…), 이리데센트, 그림체(Pink/Amber/Red) 프리셋 |
| `M_PP_JellyPaintFilter` | 포스트 프로세스 | 25 | 4 | 71 | Kuwahara 유화 필터, 스텐실 1 인 젤리에만 |
| `MF_Jelly_RedPainted_Stars` | 머티리얼 함수 | 54 | 입력 3 | – | 별 반짝이 로직을 서브그래프로 분리 |
| `MF_Jelly_RedPainted_InnerStars` | 머티리얼 함수 | 64 | 입력 4 | – | `Star Depth` 추가 — 별을 젤리 **속**에 띄움 |
| `MF_Jelly_RedPainted_InnerGlitter` | 머티리얼 함수 | 67 | 입력 4 | – | 속 별을 글리터 가루 느낌으로 |
| `M_Jelly_Gummy_RedPainted_InnerGlitter_Restored` | 머티리얼 (파생) | 398 | 46 | 2,446 | 레드 그림체 + 속 글리터 주인공 룩. 안 쓰는 파라미터 16개 정리 |
| `M_Jelly_Gummy_Gameplay` | 머티리얼 (경량) | 20 | 9 | 1,921 | 실제 게임용. 틴트·두께·불투명도만 |
| `M_LookDev_Floor` | 머티리얼 | 2 | 2 | 148 | 룩데브 바닥 |

> 경량판이 노드는 20개뿐인데 명령어가 1,921 인 이유: **Thin Translucent + Surface ForwardShading 자체의 기본 비용**이 큽니다. 빈 머티리얼로 잰 기준값:
>
> | 빈 머티리얼 (상수 색만) | 픽셀 셰이더 명령어 |
> |---|---:|
> | Opaque, Default Lit | 147 |
> | Translucent, Volumetric 라이팅 | 282 |
> | Translucent, Surface ForwardShading | 1,879 |
> | **Thin Translucent, Surface ForwardShading** | **1,897** |
>
> → 마스터(2,455)에서 젤리 효과가 추가한 건 약 560 (+30%), 경량판(1,921)은 +24 뿐. 숫자 대부분은 반투명 Forward 라이팅(라이트 루프, 반사, 포그 등) 몫이고, 실제로 다 실행되는 게 아니라 정적 추정치입니다.
> 실제 비용은 **화면에서 차지하는 픽셀 수 × 겹침(오버드로)** 으로 결정되므로 `stat gpu`, `ProfileGPU`, Shader Complexity 뷰로 측정해서 판단합니다.


## 3. 기법별 기록 — 무엇을 노드로 어떻게 풀었나

각 항목: **목표 → 노드 구성 → 유니티라면 → 배운 점**

### 3-1. 두께 기반 흡수색 (젤리 룩의 핵심)
- **목표**: 얇은 곳(귀·발끝)은 밝고 투명, 두꺼운 곳(배)은 진하고 탁하게.
- **노드**: `Mask.R(두께)` 와 `1 - Fresnel` 을 Lerp → `Power(JellyColor, 두께 × Density + 0.35)` → 두꺼울수록 DeepColor 로 Lerp
- **유니티라면**: Sample Texture 2D → Fresnel Effect → Lerp → Power. HDRP 라면 Thickness 입력을 가진 Translucent 머티리얼과 조합.
- **배운 점**: 처음 결과(단색 + 투명도)가 플라스틱처럼 보였던 원인이 바로 두께 정보 부재였음. Painter 에서 Thickness 를 굽고, 그게 안 되면 SDF 로 직접 계산해서라도 넣는 게 결정적이었음.

### 3-2. 배경이 젤리 색으로 물드는 투과
- **목표**: 젤리 너머 배경이 젤리 색으로 보이게.
- **노드**: Shading Model = Thin Translucent, `ThinTranslucentMaterialOutput` 노드에 `Lerp(흡수색, DeepColor, 두께) × TransmissionBrightness`
- **유니티라면**: URP 는 Transparent + Multiply 블렌드를 따로 그리거나 Scene Color 를 샘플해 곱하는 식으로 흉내. HDRP 는 Thin 굴절 모델 + Transmittance Color.
- **배운 점**: 일반 Translucent 는 배경을 색 없이 섞어서 뿌옇고 창백함. 출력 노드는 **정확히 하나**여야 함(두 개면 컴파일 실패).

### 3-3. 가짜 스튜디오 하이라이트
- **목표**: 레퍼런스처럼 크고 또렷한 흰 반사.
- **노드**: `Dot(ReflectionVectorWS, 고정 방향)` → `Power(…, Sharpness)` 3개 합산 → Emissive. 그림체 모드에선 `SmoothStep` + `Noise` 로 가장자리 또렷 + 일그러짐
- **유니티라면**: Reflection 노드 → Dot Product → Power / Smoothstep, Simple Noise 로 흔들기.
- **배운 점**: 반투명 Forward 셰이딩은 태양 스펙큘러만 받아 하이라이트가 빈약. 머티리얼에서 직접 "그리는" 게 스타일라이즈드 룩에 유리.

### 3-4. 림 라이트 · 무지개빛 · 다색 그라데이션
- **림**: `Power(Fresnel, RimPower)` × 좌우 방향 마스크(`Dot(VertexNormalWS, (0,1,0.25))`) → 한쪽 금색, 반대쪽 파랑
- **무지개빛**: 코사인 팔레트 `0.5 + 0.5·Cos(Fresnel·Scale + Offset + (0, .33, .67))` (Cosine 노드 Period 1)
- **그라데이션**: `(WorldPosition.z − ObjectPositionWS.z) / ObjectHeight` 로 오브젝트 기준 높이 → 3단 색, 두께로 가중해 몸통 안쪽만
- **유니티라면**: Fresnel Effect, Cosine, Position(Object) / Object 노드, Lerp.
- **배운 점**: 림 파워가 낮으면(1.5) 두 림 색이 몸통까지 번져 회색으로 탁해짐 → 2.5 이상. 그라데이션은 주색이 60% 이상 남게.

### 3-5. 그림체 — 계단 음영 · 셀 톤 · 붓 자국
- **계단 음영**: `Floor(두께 × Bands + 0.5) / Bands` (= 유니티 Posterize)
- **셀 톤**: `Dot(Normal, 빛 방향)` 을 SmoothStep 두 번 → 그림자/중간/밝은 면 3톤
- **붓 자국**: 붓질 텍스처를 **오브젝트 공간 Triplanar** 로 샘플 → R(자국 ID) 로 톤 경계를 흔들어 "붓 자국 모양 색 면"
- **유니티라면**: Posterize, Dot Product + Smoothstep, Triplanar 노드 (언리얼은 3방향 샘플 + `Abs(Normal)^k` 가중치를 직접 조립).
- **배운 점**: 흔든 값이 0~1 밖으로 나가 `Power(음수)` = **NaN** → 블룸으로 번진 초록 얼룩. 계단 결과에 **Saturate 필수**.

### 3-6. 화면 후처리 — Kuwahara 유화 필터 (Custom HLSL)
- **목표**: 손으로 칠한 질감.
- **노드**: SceneTexture(PostProcessInput0) → **Custom 노드**(Kuwahara HLSL: 4개 사분면 평균 중 분산이 가장 작은 것 선택) → CustomStencil 로 젤리만 마스크 → 밝기 0.78 이상(하이라이트·별)은 필터 제외
- **유니티라면**: Fullscreen Shader Graph + **Custom Function 노드**(HLSL), URP Renderer Feature 의 Stencil 설정.
- **배운 점**:
  - 프로젝트 설정 Custom Depth-Stencil 이 "스텐실 없음" 이면 필터가 아무 데도 안 걸림 → `r.CustomDepth=3`
  - 반투명 머티리얼은 **Allow Custom Depth Writes** 를 켜야 스텐실을 씀 (Python 이름은 `allow_translucent_custom_depth_writes`)
  - 필터 반경 6 이상이면 눈·코까지 뭉개짐 → 4
  - **디버깅 팁**: `Ignore Stencil` 파라미터로 화면 전체에 걸어 보면 "필터 문제인지 마스크 문제인지" 바로 구분됨

### 3-7. 별 반짝이 → 속 글리터 (서브그래프로 분리)
- **1차 (실패)**: 반사 벡터 공간에 별 모양 함수(`Arctangent2` + `Cosine` 으로 N각 별). 곰처럼 곡률 큰 메시에선 별이 1~3 픽셀로 쪼그라들어 안 보임.
  디버그 출력(초록 = 방향 마스크, 빨강 = 별 모양, 파랑 = 반경)으로 원인 확인.
- **2차 (채택)**: 별 스프라이트 텍스처(R 4각 / G 6각 / B 사각 점)를 오브젝트 공간 Triplanar 로 붙이고 하이라이트 쪽에서만 보이게.
- **3차 (파생 작업)**: 이 로직을 **Material Function** 으로 분리(`MF_…_Stars`) → `Star Depth` 입력을 추가해 표면이 아니라 **젤리 속에 떠 있는 별**(`InnerStars`) → 글리터 가루(`InnerGlitter`).
- **유니티라면**: Sub Graph 로 분리, Parallax / View Direction 오프셋으로 깊이감.
- **배운 점**: "같은 로직을 여러 머티리얼에서 쓰고 싶다" 가 생기는 순간 서브그래프(머티리얼 함수)로 빼는 게 맞음. 반복 수정이 한 곳에서 끝남.

### 3-8. 경량 게임용 그래프
- 441 노드 만능 마스터를 그대로 게임에 쓰지 않고, **틴트·코어 틴트·얇은/두꺼운 불투명도·시야 두께·색 리프트** 9개 파라미터, 20 노드로 따로 만듦.
- **유니티라면**: 룩데브용 그래프와 런타임용 그래프를 분리하는 것과 같음 (또는 Keyword 로 기능 스트리핑).
- **배운 점**: 노드 수보다 **셰이딩 모델 선택이 비용을 좌우**(경량판도 1,921 명령어).

## 4. 텍스처 쪽 — "그래프로 텍스처 만들기" 와의 비교

유니티에선 Shader Graph 의 노이즈 노드로 텍스처 없이 절차적으로 무늬를 만들기도 합니다. 이번엔 세 방식을 섞었습니다.

| 방식 | 사용한 곳 | 장단점 |
|---|---|---|
| **Substance Painter 레이어** (프로시저럴 마스크 + Tri-planar) | 색 얼룩, 흘러내림, 손자국, 기포, 붓 결 | 아티스트가 눈으로 조정 쉬움. 메시마다 다시 구움 |
| **Python 절차 생성** (numpy) | 붓 자국 ID 텍스처, 별 스프라이트, SDF 두께 맵 | 정확히 원하는 데이터 채널을 만들 수 있음. 코드 필요 |
| **머티리얼 그래프 안의 절차 노드** (Noise, Cosine, SmoothStep) | 하이라이트 흔들림, 무지개빛, 계단 음영 | 텍스처 메모리 0, 실시간 조절. 비싼 노드(Noise)는 비용 주의 |

> 노드로 텍스처 자체를 설계하는 도구로는 **Substance 3D Designer** 가 있습니다 (Shader Graph 와 비슷한 노드 방식으로 타일링 텍스처·.sbsar 생성). 붓 자국/별 텍스처를 Designer 그래프로 옮기면 Painter·언리얼 양쪽에서 파라미터로 조절 가능한 텍스처가 됩니다 — 다음 단계 후보.

## 5. 시행착오 요약 (재발 방지)

| 증상 | 원인 | 해결 |
|---|---|---|
| 회색·창백한 젤리 | Translucent 는 배경을 물들이지 않음 | Thin Translucent + Transmittance |
| 각진 실루엣 | 반투명 + Nanite = 거친 대체 메시 | Nanite 끄고 메시 리빌드 |
| 모래 같은 표면 | 빈 Normal 베이크가 내보내기에 섞임 | 빈 메시 맵 슬롯 비우기 |
| 젤리 전체가 기본 회색 머티리얼 | Thin Translucent 출력 노드 중복 (`delete_all_material_expressions` 가 출력 노드를 안 지움) | 출력 노드 정확히 1개 |
| 초록 빛 얼룩 | NaN 이 블룸으로 번짐 | Saturate |
| 유화 필터 안 걸림 | 스텐실 미기록 | `r.CustomDepth=3` + Custom Depth Writes |
| 별이 안 보임 | 반사 공간 별이 곡면에서 1~3px | 오브젝트 공간 스프라이트 |
| 테두리 선이 안 보임 | Fresnel 띠가 실루엣 1~2px | 띠를 안쪽으로(0.45~0.82) |
| 빨강이 회색 분홍으로 | 투과↓ 불투명도↑ → 칙칙한 BaseColor 노출 | Transmission 0.45 / Opacity 0.85 유지 |
| 파라미터를 바꿨는데 화면 그대로 | 셰이더 비동기 컴파일 중 / 인스턴스 오버라이드가 남음 | 컴파일 대기, 인스턴스 초기화 |

### 디버깅 습관으로 남길 것
1. **디버그 출력 스위치**: 의심 가는 중간값을 Emissive 로 바로 보내는 파라미터(`Debug … View`)를 잠깐 넣는다. 색 채널마다 다른 값을 넣으면 한 화면에서 여러 단계를 비교할 수 있다.
2. **양 끝값 테스트**: 효과가 안 보이면 값을 극단(×100, 초록색)으로 올려 "연결이 끊긴 건지, 값이 작은 건지" 먼저 가른다.
3. **하나씩 끄기**: 결과가 탁해지면 옵션을 하나씩 0 으로 내려 원인 파라미터를 찾는다.

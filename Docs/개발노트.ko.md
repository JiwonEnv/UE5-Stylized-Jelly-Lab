# 🛠 개발 노트 (작업용)

> 저장소 README 는 소개·갤러리용입니다. 제작하면서 필요한 프로젝트 정보는 여기에 둡니다.

## 현재 상태

- UE **5.8.4** Blueprint 기반 프로젝트. 표시 이름 **Jelly Game**, 프로젝트 파일 `JellyGame.uproject`
- 저장소 이름 `UE5-Stylized-Jelly-Lab`, 로컬 폴더 `Unreal-Engine-5-Jelly-Game`. `JellyGame` 은 프로젝트 파일 이름이자 콘텐츠 네임스페이스
- 젤리 머티리얼·룩데브까지 진행. 캐릭터 이동·젤리 변형·게임플레이는 아직 구현 전

## 개발 방향

- Blueprint 우선, 성능 측정이나 기능 요구로 필요해질 때 C++ 도입
- **WPO**: 대기·이동 중 미세한 출렁임과 표면 표현
- **충돌 이벤트 + 스프링**: 점프·착지·벽 충돌 시 메시 또는 본의 스쿼시·스트레치
- 초기 충돌 판정은 안정적인 캡슐을 유지하고 시각적 메시를 변형
- 상세 설계: [JellySystem.md](JellySystem.md)

## 개발 순서

젤리 머티리얼 ✅ → 기본 캐릭터 이동·점프 → WPO → 충돌 기반 스프링 변형 → 게임플레이 프로토타입

## 시작 방법

1. UE 5.8.4 로 `JellyGame.uproject` 를 엽니다. 시작 맵은 `Content/JellyGame/Maps/L_JellyLookDev`.
2. 젤리 에셋은 아래 `Art/` 경로에 있습니다. `Tools/BuildJellyLookDev.py` 로 룩데브 머티리얼·프리셋을 재생성할 수 있습니다.
   - ⚠️ 실행하면 프리셋 `MI_Jelly_*` 값이 스크립트 값으로 초기화되고, `MI_Jelly_RedPainted` 의 부모도 `M_Jelly_Gummy` 로 되돌아갑니다 (현재 부모는 `M_Jelly_Gummy_RedPainted`).
3. Python Editor Script Plugin · Editor Scripting Utilities 활성화됨. 스크립트 자동화에는 Project Settings → Python → **Enable Remote Execution** 필요 (`Config/DefaultEngine.ini` 에 `bRemoteExecution=True`).
4. 참고: [Painter → UE5 실습 글](SubstancePainterMCP/painter-to-ue5.ko.md), 검증 기록 `Docs/SubstancePainterMCP/ue5-validation.json`

## Git 및 LFS

- Unreal 패키지와 주요 바이너리 아트 에셋은 `.gitattributes` 의 Git LFS 규칙으로 관리합니다.
- `.uasset`/`.umap` 은 **lockable** 이라 기본으로 읽기 전용입니다. 혼자 작업할 때는 읽기 전용을 해제하고, 공동 편집 시에는 서버가 지원하면 `git lfs lock` 을 사용합니다.
- 커밋 전 `git status`, `git check-ignore`, `git check-attr filter -- <asset-path>`, `git lfs ls-files` 로 추적 대상을 확인합니다.
- 기존 바이너리 이력을 LFS 로 옮기는 이력 재작성은 별도 검토합니다.
- Word 잠금 파일(`Documents/~$*.docx`)은 커밋하지 않습니다.
